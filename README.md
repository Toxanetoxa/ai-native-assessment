# FROZA — возвраты автозапчастей поставщикам

Рабочее место сотрудника склада и коммерческого отдела. По нему можно узнать, на какую сумму возвраты остались на складе, какие позиции стоит разобрать сегодня и что уже произошло с конкретным возвратом.

[Открыть демо на GitHub Pages](https://toxanetoxa.github.io/ai-native-assessment-demo/)

## Что посмотреть в демо

| Раздел | Что можно сделать |
| --- | --- |
| **Операционные показатели** | Выберите период и поставщика, чтобы увидеть число и сумму поступлений, динамику по дням и детализацию по поставщикам. |
| **Возвраты** | Сравните общую стоимость остатка со стоимостью позиций, которые хранятся дольше 30 дней. Выберите «Срочно» в таблице приоритетов, чтобы увидеть товары с близким сроком возврата, причину приоритета и следующий шаг. |
| **Реестр возвратов** | Введите `RL-021` в поиск, нажмите «Применить» и откройте найденный возврат. В карточке видны срок возврата поставщику, отправка, решение о приёмке и финансовая запись. |

Период по умолчанию в базе — сентябрь 2026 года. В реестре фильтр отбирает позиции по дате приёмки. На странице «Возвраты» начало периода задаёт диапазон графика, а остаток на конец периода включает и товары, которые поступили раньше. Все даты рассчитываются по Москве. Стоимость остатков показывает, сколько денег заморожено в товаре. Для оценки чистого возмещения дополнительно нужны выплаты, выручка и расходы.

## Запуск фронтенда с моками

Понадобятся Node.js и npm. Версия Node.js в Docker-сборке проекта — 24.19.0. Из корня репозитория выполните команды ниже. Vite выведет локальный адрес, обычно `http://127.0.0.1:5173`.

```sh
cd web
npm ci
VITE_API_MODE=mock npm run dev
```

В этом режиме браузер использует отдельный набор демонстрационных данных, поэтому числа могут отличаться от отчётов из MySQL. Можно применять фильтры, переходить по страницам реестра и открывать карточки без запущенных Go и MySQL.

## Запуск полного приложения

Из корня репозитория запустите Docker Compose. Команда соберёт образы, поднимет MySQL, Go API и nginx и дождётся готовности всех трёх сервисов.

```sh
docker compose up --build --detach --wait
```

Откройте [приложение на localhost:8080](http://localhost:8080). Через тот же адрес nginx передаёт запросы `/api/` в Go. Проверить соединение API с MySQL можно командой `curl http://localhost:8080/healthz`. Ответ готового сервиса — `{"status":"ok"}`.

При первом запуске MySQL создаёт схему и загружает учебные записи из `db/init/`. Данные хранятся в томе `mysql_data` и сохраняются после `docker compose down`. Порты можно изменить при запуске, например `APP_PORT=8090 MYSQL_PORT=3308 docker compose up --build --detach --wait`.

При установленном `make` команде запуска соответствует `make up`. Для просмотра логов API используйте `make logs SERVICE=api`, для подключения к базе — `make db-shell`, для остановки — `make down`.

## Как устроен проект

| Путь | Содержимое |
| --- | --- |
| `web/src/` | Vue 3, TypeScript, Vue Router и графики Chart.js. Экраны находятся в `pages/`, типы ответов и вызовы API — в `api/`. |
| `cmd/server/`, `internal/httpapi/` | Запуск Go-сервера, маршруты, проверка параметров и JSON-ответы. |
| `internal/service/`, `internal/domain/` | Правила расчёта остатков, возраста и приоритета возврата, подготовка реестра и отчётов. |
| `internal/repository/`, `db/init/` | Чтение данных из MySQL 8.4, схема и учебный набор. |
| `compose.yaml`, `docker/nginx.conf` | Запуск трёх сервисов и проксирование запросов к API. |

### HTTP API

Все маршруты используют `GET`. Суммы в полях `*_minor` передаются в копейках. Для отчётов и реестра доступны параметры `from` и `to` в формате `YYYY-MM-DD`, а также `supplier_id`. Запрос ниже вернёт первые пять позиций для поставщика `SUP-A` за сентябрь.

```sh
curl 'http://localhost:8080/api/returns?from=2026-09-01&to=2026-09-30&supplier_id=SUP-A&page_size=5'
```

| Маршрут | Результат |
| --- | --- |
| `/api/meta` | Версия и дата среза, период по умолчанию, валюта, список поставщиков. |
| `/api/operations` | Поступления за период, суммы по дням и поставщикам. |
| `/api/returns-report` | Остатки на дату среза, возрастные группы, динамика и приоритетные позиции. |
| `/api/returns` | Реестр с поиском `q` и пагинацией `page`, `page_size`. По умолчанию 25 позиций на страницу, максимум 100. |
| `/api/returns/{id}` | Карточка позиции по идентификатору строки, например `RL-001`. |
| `/api/snapshot` | Полный учебный набор в JSON. |
| `/healthz` | Готовность API и доступность базы данных. |

## Проверки

Из корня репозитория выполните `make web-install`, затем `make check`. Эти команды устанавливают зависимости фронтенда, проверяют конфигурацию Compose, запускают Go-тесты, `go vet` и проверку типов TypeScript. Понадобятся Docker Compose, Go 1.27 или новее, Node.js и npm.

Тесты интерфейса запускаются отдельно из `web/` после `npm ci`.

```sh
npx vitest run --environment jsdom
```

## Публикация на GitHub Pages

GitHub Pages раздаёт статические файлы. Для публичного демо достаточно сборки Vue с моками. Для работы с общей базой Go API и MySQL потребуется запустить на сервере или контейнерной платформе. [Документация GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)

Каждый push в `main` приватного репозитория `Toxanetoxa/ai-native-assessment` запускает сборку демо в GitHub Actions. Чтобы запустить её вручную, откройте workflow и выберите **Run workflow → main → Run workflow**. [Сборка демо в GitHub Actions](https://github.com/Toxanetoxa/ai-native-assessment/actions/workflows/pages.yml)

1. В приватном репозитории CI запускает тесты фронтенда, проверяет TypeScript и собирает Vue с `VITE_API_MODE=mock`. Готовые файлы из `web/dist/` попадают в каталог `site/` ветки `main` публичного репозитория `Toxanetoxa/ai-native-assessment-demo`.
2. Push с новой сборкой запускает workflow публичного репозитория. Он упаковывает `site/` с помощью `actions/upload-pages-artifact` и публикует его через `actions/deploy-pages`. Ссылку на выпущенную версию можно открыть в завершённом запуске. [История публикаций](https://github.com/Toxanetoxa/ai-native-assessment-demo/actions/workflows/pages.yml)

| Где настроено | Параметр | Назначение |
| --- | --- | --- |
| Приватный репозиторий → Settings → Secrets and variables → Actions → Variables | `PAGES_REPOSITORY` | Значение `Toxanetoxa/ai-native-assessment-demo` задаёт репозиторий назначения и префикс URL для сборки. |
| Приватный репозиторий → Settings → Secrets and variables → Actions → Secrets | `PAGES_DEPLOY_KEY` | Закрытая часть SSH-ключа для отправки сборки. |
| Публичный репозиторий → Settings → Deploy keys | Ключ с правом **Allow write access** | Открытая часть той же пары ключей. Доступ на запись ограничен репозиторием демо. |
| Публичный репозиторий → Settings → Pages → Build and deployment | **Source → GitHub Actions** | Источником публикации служит артефакт workflow. |

Чтобы проверить ту же сборку локально, выполните из `web/` следующие команды.

```sh
npm ci
VITE_API_MODE=mock npm run build -- --base /ai-native-assessment-demo/
npx vite preview --base /ai-native-assessment-demo/
```

Откройте выведенный Vite адрес с путём `/ai-native-assessment-demo/#/returns`. Параметр `--base` задаёт префикс ресурсов, а маршрут после `#` позволяет обновить страницу или передать ссылку на нужный раздел.
